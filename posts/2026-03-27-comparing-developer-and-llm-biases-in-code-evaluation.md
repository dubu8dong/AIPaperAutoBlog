# LLM 대 인간, 코드 평가 편향

**부제:** Comparing Developer and LLM Biases in Code Evaluation

## 한 줄 결론
LLM 기반 코드 평가자는 인간 평가자 대비 12~23% 낮은 정렬 성능을 보이며, 다수의 코드 품질 항목에서 체계적 편향을 드러낸다.

## TL;DR (요약)
- LLM을 코드 심사자로 활용할 때 개발자의 실제 선호와 일치도를 평가해야 한다.  
- TRACE(Tool for Rubric Analysis in Code Evaluation)는 LLM 평가자와 인간 평가자의 편향을 자동으로 탐지한다.  
- 채팅 기반 프로그래밍, IDE 자동완성, 지시형 코드 편집의 3가지 모달리티에서 13개 모델을 비교 분석했다.  
- LLM 평가자는 최상위 모델 기준으로도 인간 대비 12~23% 낮은 정렬 성능을 보였고, 35개의 주요 편향 항목을 식별했다.  
- 예컨대 채팅 기반 코딩에서는 LLM이 긴 코드 설명을 선호하지만, 인간은 짧은 설명을 선호하는 등 품질 기준별 불일치가 관찰되었다.

## 문제 정의(Problem)
대형 언어 모델(LLM)을 코드 평가 및 피드백 도구로 활용할 때, 부분적 문맥과 모호한 의도를 포함하는 현실적 인터랙티브 환경에서 인간 선호와의 정렬(alignment)을 정확히 측정해야 한다. 기존 평가는 제한된 문맥이나 명확한 의도 하에서만 이루어져 실제 개발자 선호와의 편향을 충분히 반영하지 못한다.

## 제안 방법(Method)
연구진은 TRACE(Tool for Rubric Analysis in Code Evaluation)라는 프레임워크를 제안한다. TRACE는 다음 과정을 거친다:
- 코드 평가와 관련된 루브릭(rubric) 항목을 자동 추출  
- LLM 평가자의 점수 예측 결과와 인간 애노테이터의 선호를 비교하여 정렬 성능 측정  
이를 통해 채팅 기반 프로그래밍, 통합개발환경(IDE) 자동완성, 지시형 코드 편집의 3가지 모달리티에서 13개 LLM 평가자를 평가·비교했다.

## 핵심 기여/차별점(Contributions)
- TRACE 프레임워크 제안: 자동 루브릭 추출로 인간과 모델의 평가 편향을 체계적으로 분석  
- 3가지 인터랙티브 모달리티 평가: 채팅, IDE 자동완성, 지시형 코드 편집 환경에서 정렬도 비교  
- 35개 주요 편향 항목 식별: 기존 소프트웨어 공학 코드 품질 기준과 연관된 미스얼라인먼트 사례 도출  

## 한계/리스크(Limitations)
- 평가 대상은 13개 모델과 3개 모달리티로 제한되며, 다른 모델이나 환경으로의 일반화는 추가 검증이 필요하다.  
- TRACE가 자동 추출한 루브릭 외의 품질 지표나 미묘한 맥락적 요소는 반영되지 않을 수 있다.  
- 초록 기준으로는 데이터셋 규모 및 구체적 실험 설정 세부사항 확인이 불가하다.  

## 실무 적용 아이디어(Practical Takeaways)
- 코드 리뷰 자동화 도구에 TRACE 유사 루브릭 분석 기능을 추가해 인간 선호와 모델 편향 차이를 모니터링  
- 코드 품질 평가 시 모델 편향 항목(예: 설명 길이 선호)에 대한 보정 가중치 적용  
- 채팅 기반 코드 지원 기능 도입 시 사용자에게 최적 설명 길이 선택 옵션 제공
