# 코드형 도구 호출의 쓴 교훈

**부제:** The Bitter Lesson of Tool Calling

## 한 줄 결론
스크립트 기반 도구 호출(Programmatic Tool Calling)은 기존 JSON 호출 대비 다수 모델에서 성능 및 안정성을 향상시킨다.

## TL;DR (요약)
- 대규모 언어 모델(LLM)의 도구 호출은 전통적 JSON 인터페이스에서 코드 스텁을 활용한 호출 방식으로 진화하고 있다.  
- 논문은 BFCL v4 벤치마크에서 14개 모델을 대상으로 프로그램적 도구 호출(PTC)과 네이티브 JSON 호출을 비교했다.  
- PTC는 11/14 모델에서 JSON 호출을 능가하며, GPT-5.6 계열에서 10.6% 성능 개선을 보였다.  
- 병렬 호출(fan-out)과 문맥 부패(context rot) 상황에서도 대부분 모델이 PTC에서 우위를 유지했다.

## 문제 정의(Problem)
대규모 언어 모델이 API 도구를 활용해 훈련 데이터 범위를 벗어난 행동을 수행할 수 있으나, 
기존의 JSON 호출 방식은 엄격한 포맷 제약으로 인해 복잡한 워크플로우 개발에 한계가 있다. 
코드 수준의 도구 호출에 대한 체계적 비교 실험과 세대별 모델 성능 추적은 아직 부재하다.

## 제안 방법(Method)
- 프로그램적 도구 호출(Programmatic Tool Calling, PTC) 패러다임을 정의:  
  Python 타입 힌트가 포함된 도구 스텁(stub)을 언어 모델에 노출하고, 모델이 해당 스텁을 호출하는 형태로 설계.  
- 단일 에이전트 턴에서 코드 실행 및 결과 반환을 일괄 처리하도록 구성.  
- BFCL v4 벤치마크를 활용하여 14개 주요 언어 모델(GPT-3.5, GPT-4, GPT-5 계열 등)에서 PTC와 네이티브 JSON 호출을 비교 평가.  
- 병렬화(fan-out) 및 문맥 부패(context rot) 조건 하에서도 성능 차이를 측정.

## 핵심 기여/차별점(Contributions)
- PTC와 JSON 호출의 체계적 비교: BFCL v4 벤치마크를 통한 14개 모델 실험 설계  
- PTC가 11/14 모델에서 JSON 호출을 능가, 특히 GPT-5.6 계열에서 10.6% 성능 개선  
- 병렬 호출 및 문맥 부패 상황에서도 13/14 모델에서 PTC가 안정적인 성능 우위 유지

## 한계/리스크(Limitations)
- 실험은 BFCL v4 벤치마크에 국한되어 있어, 다른 도메인·태스크 일반화 가능성은 초록 기준으로는 확인 불가  
- 보안·오버헤드·실제 운영 환경에서의 확장성 등 추가 요소는 초록 기준으로는 확인 불가  

## 실무 적용 아이디어(Practical Takeaways)
- LLM 기반 에이전트 설계 시 Python 도구 스텁을 활용한 PTC 도입을 검토하여 복잡한 워크플로우를 자연스럽게 처리  
- 장애 포인트가 많거나 긴 문맥 유지가 필요한 서비스에서는 PTC의 문맥 부패 저항성을 테스트  
- 모델 버전 업그레이드 시 기존 JSON 호출 로직을 재평가하고, PTC로 전환할 때의 성능 변화를 모니터링
