# TokTier 상태 토크나이징
**부제:** TokTier: Exact Stateful Tokenization for Agentic LLM Serving

## 한 줄 결론
TokTier는 세션 단위 증분 토크나이징과 GPU 기반 풀 토크나이징을 결합해 최대 437배 빠른 상태 토크나이징을 실현한다.

## TL;DR (요약)
- 기존 대형 언어 모델(LLM) 서빙 시스템은 프롬프트 키-값 캐시는 활용하지만, 매 호출마다 전체 요청 텍스트를 재토크나이징해 시간 비용이 크다.  
- TokTier는 세션별로 추가된 텍스트 주변만 재토크나이징하며 안정 경계(stable boundary) 검사 후 스플라이스(splice)해 정확도를 유지한다.  
- 재사용 불가능한 콜에는 GPU에서 전 처리(pre-tokenization)와 바이트 페어 인코딩(BPE)을 완전 수행하고, 샘플링 검증을 통해 토크나이징 일관성을 보장한다.  
- 증분 수리(incremental repair)는 100K~3M 문자 구간에서 0.5~1.1ms 소요로 Hugging Face 대비 최대 437배 빠르며, GPU 풀 토크나이징은 1M문자를 0.87ms에 처리한다.  
- vLLM 연동 시 토크나이징 시작까지 지연 시간이 중간값 기준 16~34% 단축되고 P99는 23% 감소했다.

## 문제 정의(Problem)
- LLM 서빙 시스템은 내부적으로 프롬프트 키-값 상태를 캐싱하지만, 프론트엔드 레이어는 여전히 전체 입력 텍스트를 매번 재토크나이징한다.  
- 코딩 에이전트(agentic) 활용 시 긴 대화 이력을 작은 툴 호출 결과마다 재전송하며, 짧은 추가만으로도 이전 시퀀스 끝부분의 토큰 경계가 변경되어 재사용이 어렵다.  
- 실제 두 개의 에이전트 생태계에서 153,951개의 호출을 분석한 결과, 중앙값 추가 길이는 약 1.4K자이며, 1.0~3.6% 호출만이 수백만 자 이상의 문맥을 재시작 또는 재빌드한다.  
- 전체 호출의 94.1%는 프롬프트 캐시 히트가 발생해도, 토크나이징이 첫 토큰 생성까지 걸리는 시간의 최대 64%를 차지해 지연 병목으로 작용한다.

## 제안 방법(Method)
- 세션 연속 호출: 요청된 추가 텍스트 주변의 윈도우(window)만을 재토크나이징하고, per-request 안정 경계 검사를 통과하면 기존 토큰 시퀀스에 스플라이스(splice)한다. 실패 시 윈도우 크기를 확장하거나 전체 재토크나이징으로 대체한다.  
- 신규 세션 또는 재사용 불가(prefix 없음) 호출: GPT 계열의 정규 표현식 기반(pre-tokenization) 룰을 로컬 실행 규칙으로 분해한 뒤, GPU에서 정확한 전 처리(pre-tokenization)와 바이트 페어 인코딩(Byte Pair Encoding, BPE)을 수행한다.  
- 실시간 안정성 보장을 위해 샘플 기반 섀도우 검증기(shadow verifier)를 운영하며, 라이브 트래픽에서 무작위 샘플을 추출해 원본 토크나이징과의 차이를 확인한다.

## 핵심 기여/차별점(Contributions)
- 상태 유지 토크나이징: 전체 재토크나이징 없이 세션별 증분 처리만으로도 원본과 동일한 토큰 ID를 보장하는 계약(Exactness)을 제시  
- 고성능 증분 수리: 100K~3M 문자 구간에서 0.5~1.1ms 처리로 Hugging Face 대비 최대 437배, Gigatoken 대비 1M 문자 기준 2.1배 빠른 속도 구현  
- GPU 풀 토크나이징 엔진: 1M 문자 입력을 0.87ms에 인코딩해 Hugging Face 대비 최대 491배, 기존 CPU 대비 23.4배 빠른 처리 성능 달성

## 한계/리스크(Limitations)
- 윈도우 기반 안정 경계 검사 실패 시 전체 토크나이징으로 되돌아가며 퍼포먼스 저하가 발생할 수 있다.  
- 샘플링된 섀도우 검증만으로 토크나이저 불일치 문제를 완전 차단할 수 있는지는 초록 기준으로는 확인 불가하다.  
- GPU 리소스와 복잡한 룰 분해 로직 도입에 따른 운영 및 비용 부담 평가는 초록만으로는 확인 불가하다.

## 실무 적용 아이디어(Practical Takeaways)
- LLM 서빙 파이프라인에 상태 유지 증분 토크나이저 모듈을 삽입해 토크나이징 레이턴시를 크게 줄일 수 있다.  
- 대규모 요청 처리 시 GPU 기반 전 처리 및 BPE 오프로드를 고려해 전체 워크로드 성능을 향상시키자.  
- 안정 경계 검사와 샘플 기반 검증 로깅을 도입해 오토토크나이저와 일관성 모니터링 체계를 구축하자.
